# [bisu.com.np](https://bisu.com.np)

Portfolio of **Bisu Ghalan** — CS student and security researcher from Nepal. Built with Next.js (pages router), React, Tailwind CSS v4, TypeScript, and Biome, running on Bun.

## Stack

| Concern | Choice |
| --- | --- |
| Framework | Next.js 16 (Turbopack, pages router) |
| UI | React 19 + Tailwind CSS v4 (CSS-first `@theme` in `styles/main.css`) |
| Types | TypeScript 7 |
| Lint / format | Biome |
| Package manager | Bun |

## Development

```bash
bun install
bun run dev        # http://localhost:3000
```

| Script | Purpose |
| --- | --- |
| `bun run dev` | Dev server |
| `bun run build` | Static export to `out/` (every route prerendered) |
| `bun run start` | Serve the exported `out/` locally |
| `bun run sitemap` | Regenerate `public/sitemap.xml` (run after changing routes or projects) |
| `bun run typecheck` | `tsc --noEmit` |
| `bun run check` | Biome lint + format (writes) |

## Deploy

The build is a **static export** (`output: "export"` in `next.config.ts`): `bun run build` writes a self-contained `out/` directory that any static host can serve. There is no server runtime, no API routes, and no image optimizer — images are pre-sized WebP, and `public/sitemap.xml` is generated by `bun run sitemap`.

Because the export contains both `projects.html` and a `projects/` directory, hosts resolve `/projects` to `projects.html` (Cloudflare Pages and Netlify do this natively; Vercel needs the `cleanUrls: true` already set in `vercel.json`). After the first deploy, confirm with `curl -I https://bisu.com.np/projects` — a 200 means clean URLs resolve, a 404 means the host needs `trailingSlash: true` plus matching canonicals.

Headers are defined three times on purpose, since export mode ignores `headers()` in `next.config.ts`: `public/_headers` (Cloudflare Pages, Netlify), `vercel.json` (Vercel), and `netlify.toml`.

### Vercel

Import the repo — Next.js is detected, `out/` is picked up automatically. Or from the CLI:

```bash
bunx vercel deploy --prod
```

### Netlify

`netlify.toml` already sets the build command and publish directory, so a Git-connected site needs no dashboard config. Or from the CLI:

```bash
bunx netlify deploy --prod --dir=out
```

### Cloudflare Pages

Git-connected: pick the **Next.js (Static HTML Export)** preset, build command `bun run build`, output directory `out`. Or deploy the built directory directly (`wrangler.jsonc` already points at `out`):

```bash
bun run build
bunx wrangler pages deploy out
```

Then submit `https://bisu.com.np/sitemap.xml` in Google Search Console and Bing Webmaster Tools.


## Content

All copy lives in data files — no CMS, no database.

| File | Contents |
| --- | --- |
| `data/content/home.ts` | Skills, experience, education, testimonials |
| `data/content/projects.ts` | Projects and their tags (`/projects/tag/*` pages are generated from these) |
| `data/global.ts` | Routes and footer columns |

Design tokens (colors, fonts, animations) are defined once in the `@theme` block in `styles/main.css`.
